## 四、5/15 分钟资金增量的两个基准来源

A/B 类资金门槛要判定「最近 5 分钟主力是否在流入」。这个增量有两个来源，代码按可用性择优，**不会用 0 或猜测值补缺**：

| 来源 | 机制 | 成本 | 数据完整度标签 |
|---|---|---|---|
| 本地快照（`flow_snapshot.json`） | 当前累计主力净额减 3–7 分钟前的快照 | **零额外请求** | `含连续快照` |
| 东财当日累计分钟序列（兜底） | 一次拿 240 根 1 分钟累计值，按时间取端点作差（**只在最后一段连续分钟里算**） | ≤20 请求/轮，仅缺基准时发起 | `含分钟序列` |

兜底存在的理由：快照差分要求同一天至少跑过两轮，**冷启动、断点重启、隔日首轮都会让增量变成「基准不足」**，而它是 A/B 类资金门槛的判定项——缺失时门槛无法评估，候选会被整体压成「数据不足」。

兜底数据的校验规则：

- **bar 日期必须等于本次行情快照所属交易日**（取全市场行情的时间戳，不按自然日判断），隔日序列按过期拒绝；周末/盘后跑快照时仍然有效。
- 盘中额外要求末根 bar 不落后超过 10 分钟。
- **窗口必须按时间取，不能按记录条数取**：序列在午休（11:30 → 13:01）与接口缺 bar 处会出现时间缺口。只在最后一段「每分钟连续」的区间内计算窗口；连续段不够长就返回"无法核验"。2026-09-26 实测过按条数取的反例：13:03 时 `[-6]` 取到 11:28，会把约 95 分钟的累计变化当成 5 分钟增量，直接影响资金门槛与连续性判断。
- 校验不过即返回空，该只保持「基准不足」。
- 分钟序列不足 15 根时（含午后刚开盘的连续段不足），15 分钟增量仍记基准不足，只有 5 分钟增量可用。

同一份序列还用于三处**判定**（不额外增加请求，共享 60 秒缓存与每轮预算）：

| 用途 | 取哪一列 | 无法核验时 |
|---|---|---|
| 5/15 分钟增量 | `f52` 主力净额 | 保持"基准不足"，门槛不放行 |
| 低吸高位派发核验（5日涨幅≥12% + 主力持续净流出） | `f52`（等间隔采样，口径对齐快照的累计值） | 记数并在报告顶部提示"未能核验、按未触发处理"，不静默跳过 |
| `coalition` 连续性（连续两期主力与超大单均未衰减） | `f52` 与 `f56` **两列都要通过** | 按原规则拒绝——只用主力核验等于放松门槛 |

## 五、三类故障：限流、路径下线、WAF 拦截

三者现象相似，处理方式完全不同，排查时先分清：

| | 限流 | 路径下线 | WAF 拦截 |
|---|---|---|---|
| 现象 | 请求被暂时拒绝/变慢 | 接口本身不再提供服务 | 返回 HTML 拦截页而非 JSON |
| 典型响应 | 空响应、超时、间歇失败 | 标准路由 nginx **502**；部分路径直接断连 | `waf.tencent.com/501page.html` |
| 恢复方式 | 等待即可 | 只能改用其他路由 | 降低请求强度或改用其他源 |
| 代码对策 | 2 并发、指数退避、缓存复用 | 换用 `/webguest` 路由、多源降级 | **连续失败熔断该主机**，走降级源，不逐只重试 |

2026-09-25 实测记录（用于区分路径下线）：

- `push2.eastmoney.com` 上 `/api/qt/clist|stock/get|trends2|fflow` 返回 nginx **502**（后端下线），而同一台服务器上 `/webguest/*` 全部正常、`/api/qt/stock/details/get` 也正常 —— 是**按端点逐个下线**，不是按调用方拒绝。
- `push2his.eastmoney.com` 的 `kline`/`trends2`/`fflow 分钟` 断连，同主机 `fflow/daykline` 正常；该主机没有 `/webguest`。
- `push2delay` 的标准 `clist` 同样返回 502。
- `1/3/5/.../92.push2.eastmoney.com` 共 18 个子域名，固定 IP 对照测试：标准 `/api/` 全部不可用，`/webguest/` 全部返回正常数据。
- 判断依据是「同一 IP 上不同路径生死不同」，因此不是 IP 封禁、不是请求头校验，也不是频率问题 —— 补 `ut` token、`Referer`、`Origin` 均无效。

2026-09-26 实测记录（WAF 拦截与放大效应）：

- 腾讯日 K `web.ifzq.gtimg.cn/appstock/app/fqkline/get` 在**代理与直连下都**返回 WAF 拦截页；同一时间腾讯实时行情 `qt.gtimg.cn` 正常 —— 接口级拦截，不是网络不通、也不是出口 IP 被封。
- 未加熔断时：一轮 76 只候选逐只重试并叠加多路径失败，单轮请求从 167 放大到 **1173**，耗时 22.9s → 39.9s，且整轮日 K 降级到新浪。
- 加熔断后（连续失败 3 次暂停 600 秒）：同样场景单轮请求 **286**、耗时 30.9s，腾讯请求数 304 → 24。
- 降级到新浪会改变均线口径（新浪可能返回不复权价），因此报告头部的数据来源改为按本轮实际来源生成，不再写死。

## 六、排查方法论：先绕开本机代理

本机装有代理软件（Fake-IP / TUN 模式）时，**所有域名解析都会被改写**（例如东财域名统一解析到 `198.18.x.x`），此时代码里的「直连」仍然走隧道，看到的现象未必是服务端的真实响应。

判断东财侧真实行为时，用 DoH 取真实 IP 再直连：

```bash
# 取真实 IP（Cloudflare DoH）
curl -s -H "accept: application/dns-json" \
  "https://cloudflare-dns.com/dns-query?name=push2.eastmoney.com&type=A"

# 绕过隧道直连该 IP（保留 SNI 与 Host）
curl -s --resolve push2.eastmoney.com:443:<真实IP> \
  "https://push2.eastmoney.com/webguest/api/qt/clist/get?pn=1&pz=2&fs=m:1+t:2&fields=f12,f14" \
  -A "Mozilla/5.0" -w "\n[HTTP%{http_code}]\n"
```

反例记录：2026-09-25 在隧道内看到 `ConnectionError`，一度被判断为「东财按 IP 封禁」；绕开隧道后实际是 **502**（服务下线）。结论方向因此完全不同 —— 前者会引导去换节点/换 IP（无效），后者才指向换路由（正确）。

## 七、调参纪律

1. **分页并发 2 不要调整。** 该值是实测边界（3 并发触发过持续限流），不是保守取值。要提速优先优化缓存与请求合并。
2. 新增任何周期性请求前，先确认它不会与 90 秒主循环叠加成新的峰值。
3. **兜底类请求必须是「按需 + 有界 + 有缓存」**：分钟序列兜底就是按这个模式做的（只在缺基准时发起、每轮上限 20 只、0.4 秒间隔、60 秒缓存）。不要把它改成每轮固定拉取。
4. **失败要有熔断，不能让失败放大请求**：一次失败会按「主机数 × 路径数 × 重试数」放大，76 只候选逐只重试就能把 167 做成 1173。任何新增的批量请求都要配连续失败熔断（参考腾讯日 K 的 3 次 / 600 秒）。
5. 修改频率相关参数后，回来更新本文件，并用附录方法复测一次。

## 附录：测量方法

给引擎的 HTTP 出口挂计数器，实跑一轮后按「主机 + 路径」汇总。核心是替换 `requests.Session.request` 与 `urllib.request.OpenerDirector.open`：

```python
import collections, re, sys, threading, urllib.request
sys.path.insert(0, "daily-stock-analysis/scripts")
import requests

CALLS = collections.Counter()
LOCK = threading.Lock()

def _key(url):
    host = url.split("/")[2]
    path = "/" + "/".join(url.split("/")[3:])
    return f"{host}{path.split('?')[0]}"

_sess_req = requests.Session.request
def sess_req(self, method, url, *a, **kw):
    with LOCK:
        CALLS[_key(url)] += 1
    return _sess_req(self, method, url, *a, **kw)
requests.Session.request = sess_req

_urlopen = urllib.request.OpenerDirector.open
def opener_open(self, fullurl, *a, **kw):
    u = fullurl if isinstance(fullurl, str) else getattr(fullurl, "full_url", "?")
    with LOCK:
        CALLS[_key(u)] += 1
    return _urlopen(self, fullurl, *a, **kw)
urllib.request.OpenerDirector.open = opener_open

import a_share_daily_screen as screen
sys.argv = ["a_share_daily_screen.py", "--format", "md", "--save", "/tmp/freq_check.md"]
screen.main()

for k, n in CALLS.most_common():
    print(f"{k:70} {n:4}")
```

注意：看板的路径探测会随候选端口数量增加请求数（每多一条代理路径，两个辅助探测端点各多 1 次请求），上表数字对应 `proxy_ports.json` 当时的配置。
