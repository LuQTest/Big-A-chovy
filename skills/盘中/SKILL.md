# 盘中 · 项目唯一执行入口

定位同时包含 `AGENTS.md`、`选股框架.md`、`筛选结果/`、`决策记录/` 的项目根目录。先读 `AGENTS.md`、[选股框架](../../选股框架.md)、[工作流](../../CLAUDE.md)及最新决策记录。本文件只规定执行步骤，阈值、实验权限、买卖裁决与七项支撑均引用框架，不在这里复制。已安装的旧版skill已停用。

## 选择输入范围

- `/盘中` 或首次“看盘”：按文件名时间戳取当日最新报告；为资金连续性、信号锁定补读必要前序快照。
- “继续看筛选”或 `ggp`：读取上次提问到当前的所有报告；边界未知从当天首份开始，注明覆盖范围。
- `/盘中 决策 1030` 或 `20260804_1410`：读取指定时点及判断所需的前序快照，不能以之后数据冒充当时事实。
- 盘中报告超过10分钟标时效问题，补查实时数据；当日报告缺失不能把旧日当成今日。
- 报告按表头动态解析，批量扫描核对样例行；报告消失、空结果、缺字段均要查明原因。

## 决策与ggp

1. 从最新决策记录恢复三类持仓、现金、在盯和T+1可卖状态；可用 `python3 tools/get_position.py --json`。
2. 先核对已有在盯与持仓的状态变化，再扫描新候选；覆盖报告所有候选池及明日观察池。
3. 按框架核验信号、正式/实验权限、公告、资金连续性、主导、板块、买点、分笔五档、盈利状态与YTD。用项目行情和基本面工具补证据，缺数据如实列卡点。
4. 按框架四层裁决。真实仓建议逐只展示七项支撑及T+1计划；模拟实验注明类别和权限；仅影子采样的信号不改写成可买。
5. 按CLAUDE.md日志格式落盘本次范围、结论、在盯变化与计划。建议挂单与实际成交分开记录，不自动下单。

## 盘问与复盘

- `/盘中 盘问 <代码或名称>`：先摆出资金、盘口、基本面、买点与盈亏比事实，再列规则结论；独立互动盘问可围绕剩余关键问题一次一问，ggp内直接完成查证。
- 用户报告买卖：立即追加当日【执行】记录，核对清单内/外及价格偏差；缺数量、价格、日期不猜测。更新持仓时区分真实、模拟、解套仓。
- `/盘中 复盘`：核算实际与模拟执行结果，检查信号衰减、板块退潮、买点偏差；收盘更新结构化持仓快照，经验与实验进度按框架维护。

## 输出与隐私

普通输出遵循 [ggp显示约定](../../docs/ggp_display_prompt.md)；仅机器通道读取 [ggp协议](../../docs/ggp_prompt.md)。工具命令与网络代理用法见README和CLAUDE.md。

所有报告、决策记录、持仓、影子样本与账户资料只留本地，不提交GitHub或发送外部服务。
